# دليل بناء KOPT X والتحديث التلقائي

> ملف تعليمي، تعطيه لـ Claude Code (أو لأي مطوّر) ليفهم كيف بُني هذا التطبيق، وكيف يتحدّث وحده على الويب والأندرويد، وكيف يُبنى تطبيق مثله من الصفر.
> كل ما هنا مأخوذ من الكود الفعلي في هذا المستودع (الإصدار 9.9.1). التفاصيل الدقيقة والتاريخ موجودة في [`PROJECT_MEMORY.md`](../PROJECT_MEMORY.md) والقواعد المختصرة في [`CLAUDE.md`](../CLAUDE.md).

## 1. الفكرة العامة

تطبيق شخصي لإدارة متجر صغير (مخزون، مبيعات، مصاريف، ديون، موردون، زبائن، فواتير). أهم قرارات التصميم:

| القرار | السبب |
|---|---|
| **كل البيانات على الجهاز** (IndexedDB) ويعمل بدون إنترنت | خصوصية، لا خادم ولا تكلفة، يعمل في أي مكان |
| **JavaScript عادي بدون إطار ولا أدوات بناء** | ملفات قليلة تُنسخ كما هي؛ نفس الملفات تعمل في المتصفح وداخل تطبيق الأندرويد |
| **نسخة ويب (PWA) هي الأساس** على GitHub Pages | مجانية، رابط واحد، تتحدّث وحدها |
| **تطبيق أندرويد (APK) يغلّف نفس ملفات الويب** عبر Capacitor 6 | ميزات الهاتف (كاميرا، بصمة، اهتزاز، إشعارات، حفظ ملفات) |
| **التحديث يصل للأندرويد كملف zip من الموقع نفسه** | لا حاجة لإعادة تثبيت APK عند كل تعديل |

## 2. الملفات

```
index.html    الهيكل: الشريط العلوي، #v المحتوى، زر +، شريط التنقل
app.css       نظام التصميم (Titanium × Burgundy Liquid Glass) — المتغيرات في :root
i18n.js       window.EN = { 'النص العربي': 'English', … }
core.js       APP_VER، L() للترجمة، الحالة S، IndexedDB، تنسيق الأرقام، الحسابات المالية، الصفحات والنوافذ، الصور، جسر الهاتف
views.js      الرئيسية، الرسم البياني، المنتجات، المبيعات، الديون، المصاريف
more.js       الموردون، الإشعارات، مركز البيانات، الإعدادات، التقارير، البحث، التحديث الذاتي، التشغيل
extra.js      الفواتير، الباركود، البصمة، النسخ الاحتياطي، السلة، الصندوق، الأنواع… (يُحمَّل آخرًا)
sw.js         Service Worker: العمل بدون إنترنت + تحديث نسخة الويب
manifest.json بيانات الـ PWA
tools/publish-web.sh   ينسخ الملفات إلى gh-pages ويصنع حزمة التحديث للأندرويد
tests/        اختبارات Playwright
.github/workflows/      بناء APK و IPA، إنشاء مفتاح التوقيع، فحص الموقع المباشر
```

الملفات `<script>` عادية تتشارك نطاقًا واحدًا وتُحمَّل بالترتيب: `i18n → core → views → more → extra`. لذلك يستطيع `extra.js` أن **يغلّف** دوال من الملفات السابقة بدل تعديلها، مثل:

```js
const _vHome0 = vHome;
vHome = function(){ const h = _vHome0(); /* أضف شيئًا */ return h; };
```

## 3. البيانات (لا تكسرها أبدًا)

- قاعدة IndexedDB اسمها `pbm` إصدار 5، فيها المخازن: `p` منتجات، `s` مبيعات، `e` مصاريف، `d` ديون، `sp` موردون، `t` مهام، `l` سجل، `k` إعدادات، `img` صور (Blob).
- **لا تغيّر أسماء المخازن ولا الحقول.** أي حقل جديد يكون اختياريًا وله قيمة افتراضية (مثل `s.o` رقم الطلب، `p.vg` مجموعة الأنواع).
- **البيع لقطة ثابتة**: يحفظ الاسم وتكلفة القطعة `uc` وسعر الصرف وقت البيع، فحذف المنتج أو تغيير سعره لا يغيّر الأرباح القديمة.
- **الحسابات المالية في مكان واحد** (`core.js`): `sRev` الإيراد، `prof` الربح، `AGG(a,b)` مجموع فترة. **الديون لا تدخل في الربح أبدًا** حتى لا يُحسب المبلغ مرتين.
- كل تعديل يمر عبر `put`/`del` التي تزيد العدّاد `DV`، والقيم المحسوبة تُخزَّن بـ `memo()` وتُعاد فقط عند تغيّر `DV` (هذا سبب سرعة التطبيق).

## 4. اللغة والاتجاه

- كل نص يظهر للمستخدم يُكتب بالعربي داخل `L('…')`، وترجمته الإنجليزية في `i18n.js`.
- سكربت يتأكد أن كل نص عربي له ترجمة (يجب أن يطبع قائمة فارغة):

```bash
node -e "global.window={};require('./i18n.js');const fs=require('fs');const k=new Set();for(const f of ['core.js','views.js','more.js','extra.js'])for(const m of fs.readFileSync(f,'utf8').matchAll(/'((?:[^'\\\\\n]|\\\\.)*)'/g))if(/[؀-ۿ]/.test(m[1]))k.add(m[1]);console.log([...k].filter(x=>!(x in window.EN)))"
```

- CSS منطقي (`margin-inline-start` بدل `margin-left`) حتى يعمل الاتجاهان RTL و LTR.

## 5. التحديث التلقائي — الجزء الأهم

هناك **مساران** لأن التطبيق يعمل بطريقتين:

```
                       ┌──────────────────────────────┐
  git push gh-pages →  │  GitHub Pages (الموقع)        │
                       │  index.html, *.js?v=991 …     │
                       │  version.json                 │──┐
                       │  koptan-9.9.1.zip             │  │
                       └──────────────┬───────────────┘  │
                                      │                  │
              ┌───────────────────────┘                  │
              ▼                                          ▼
   نسخة الويب (PWA)                            تطبيق الأندرويد (APK)
   Service Worker يجلب الملفات الجديدة          يقرأ version.json، ينزّل zip،
   ثم يعيد تحميل الصفحة                          ويبدّل الملفات داخله ثم يعيد التشغيل
```

### 5.1 ما الذي يُنشر (tools/publish-web.sh)

1. ينسخ ملفات التطبيق إلى نسخة من فرع `gh-pages`.
2. يصنع **`koptan-<الإصدار>.zip`**: نفس الملفات، **في جذر الملف المضغوط** (بدون مجلد داخلي)، لأن مكوّن التحديث في الأندرويد يتوقع `index.html` في الجذر.
3. يكتب **`version.json`**:

```json
{"version":"9.9.1","zip":"https://koptan919.github.io/KOPTX/koptan-9.9.1.zip"}
```

الإصدار يُقرأ تلقائيًا من `const APP_VER='9.9.1'` في `core.js`.

### 5.2 رقم الإصدار يجب تغييره في 4 أماكن عند كل نشر

| المكان | المثال | لماذا |
|---|---|---|
| `core.js` | `APP_VER='9.9.1'` | المقارنة مع `version.json` |
| `index.html` | `core.js?v=991` (للملفات الخمسة و CSS) | كسر ذاكرة المتصفح المؤقتة |
| `sw.js` | `V='koptan-v9.9.1'`, `Q='?v=991'` | تغيّر ملف الـ SW = المتصفح يكتشف نسخة جديدة |
| `manifest.json` | `"version": "9.9.1"` | للتوثيق |

### 5.3 مسار الويب (Service Worker)

في `sw.js`:
- **التثبيت**: يحفظ كل الملفات (بـ `?v=`) في كاش اسمه `koptan-v<الإصدار>` ثم `skipWaiting()`.
- **التفعيل**: يحذف الكاشات القديمة ثم `clients.claim()`.
- **فتح الصفحة (navigate)**: **الشبكة أولًا** مع مهلة 3.5 ثانية، وإذا لا يوجد إنترنت يعرض `index.html` من الكاش. لذلك النسخة الجديدة تظهر عند الفتح التالي.
- **الملفات ذات `?v=`**: من الكاش أولًا (لا تتغير أبدًا لأن الرقم يتغير مع كل إصدار).

في `more.js` (عند التشغيل، وليس داخل تطبيق الأندرويد):
- يسجّل `sw.js` ويستدعي `registration.update()` عند الرجوع للتطبيق (`visibilitychange`) وعند عودة الإنترنت (`online`).
- عند `updatefound` → إذا كان هناك SW سابق (ليس أول تثبيت) يعرض «جارٍ تحديث التطبيق…»، وعندما يصبح الجديد `activated` يقرأ `version.json`، **وإذا كان أحدث فقط** من `APP_VER` الحالي يعيد تحميل الصفحة، بعد أن يُغلق المستخدم أي نموذج مفتوح.

### 5.4 مسار الأندرويد (Capacitor + @capgo/capacitor-updater)

**الإعداد عند البناء** (`build-apk.yml`):

```json
"plugins": { "CapacitorUpdater": {
  "autoUpdate": false,        // وضع يدوي: التطبيق نفسه يقرر متى يتحدث
  "statsUrl": "",             // لا يرسل أي إحصائيات لأي خادم
  "appReadyTimeout": 15000,   // إذا لم تقل الحزمة الجديدة "أنا جاهزة" خلال 15 ثانية → رجوع تلقائي للقديمة
  "resetWhenUpdate": true     // عند تثبيت APK جديد يبدأ من ملفاته هو
}}
```

**عند التشغيل** (`more.js`):
1. `notifyAppReady()` فورًا: يقول للمكوّن «هذه الحزمة تعمل»، وإلا يرجع للنسخة السابقة تلقائيًا (حماية من تحديث معطوب).
2. بعد 2.5 ثانية `selfUpdate(false)`، وأيضًا عند الرجوع للتطبيق وعند عودة الإنترنت، **مرة كل ساعة كحد أقصى** (إلا إذا فشلت المحاولة السابقة).

**دالة `selfUpdate`** خطوة بخطوة:

```js
const r = await fetch(UPD_URL + '?t=' + Date.now(), {cache:'no-store'});  // version.json
const j = await r.json();
if (!newer(j.version, APP_VER)) return;              // مقارنة أرقام: 9.10.0 > 9.9.1
toastP('جارٍ تحديث التطبيق إلى الإصدار ' + j.version);
const b = await capCall('CapacitorUpdater','download',{url:j.zip, version:j.version});
await capCall('CapacitorUpdater','next',{id:b.id});  // أولًا: يُطبَّق في التشغيل القادم حتى لو انقطع شيء
whenIdle(() => {                                     // ينتظر إغلاق أي نموذج مفتوح (لا تضيع بيانات المستخدم)
  toast('تم تنزيل التحديث — جارٍ إعادة التشغيل…');
  setTimeout(() => capCall('CapacitorUpdater','set',{id:b.id}), 1500);  // يبدّل الآن ويعيد التحميل
});
```

النتيجة: المستخدم يرى رسالتين ويتحدث التطبيق وحده بدون أي زر.

**متى نحتاج APK جديد فعلًا؟** فقط عند تغيير شيء «أصلي»: إضافة plugin، صلاحية، أيقونة التطبيق، اسمه على الشاشة. كل تعديل في HTML/CSS/JS يصل بالتحديث الذاتي.

### 5.5 توقيع الـ APK (مهم جدًا)

- الهاتف يقبل تثبيت APK فوق القديم **فقط إذا كان التوقيع نفسه**.
- مفتاح «debug» على GitHub Actions يُنشأ عشوائيًا في كل بناء ← كل APK يحتاج حذف التطبيق (وضياع بياناته).
- الحل المطبّق: workflow **Create signing key** يُشغَّل **مرة واحدة**: يولّد مفتاح RSA-4096، يشفّره بـ AES-256 بكلمة سر من سر المستودع `KEYSTORE_PASSWORD`، ويحفظ الملف المشفّر `signing/koptan.jks.enc` + بصمته `signing/fingerprint-sha256.txt`. المفتاح الأصلي لا يغادر الخادم.
- **Build APK** يفك التشفير، يوقّع، ويتأكد أن بصمة الـ APK **تطابق** البصمة المحفوظة، وإلا يفشل.
- **لا تحذف ولا تستبدل المفتاح أبدًا**، ولا تطبع كلمة السر.

### 5.6 مشاكل حقيقية واجهناها وحلولها

| المشكلة | الحل |
|---|---|
| updater 6.53 يحتاج compileSdk 35 | تثبيت الإصدار `@capgo/capacitor-updater@6.25.6` |
| ما زال يسحب `androidx.work 2.11` | `resolutionStrategy.force "androidx.work:work-runtime:2.9.1"` في `android/build.gradle` |
| play-services يحتاج minSdk 23 | تغيير `minSdkVersion = 23` (أندرويد 6+) |
| زر الرجوع في الهاتف يخرج من التطبيق | Capacitor نفسه لا يعالج الرجوع؛ يجب إضافة `@capacitor/app` والاستماع لـ `backButton` |
| نُشر إصدار أقدم فوق أحدث على gh-pages | قبل أي نشر: `git show origin/gh-pages:version.json` يجب ألا يكون أحدث من فرعك |
| لوحة مفاتيح عربية تكتب ٠-٩ فيُرفض الـ PIN | لوحة أرقام داخل التطبيق + تحويل الأرقام العربية `normD()` |
| فتح الوجه لا يظهر على Oppo/Realme/Xiaomi | هذه الهواتف لا تعطي الوجه للتطبيقات؛ نعرض السبب بدل إخفاء الخيار |

## 6. الاختبارات (قبل أي نشر)

```bash
tests/run.sh          # 42 فحص شامل + 33 فحص ميزات + التحديث الذاتي + ترقية الـ SW
tests/run.sh shots    # + صور لكل الشاشات وفحص عدم خروج المحتوى عن الشاشة
```

- يُشغّل خادمًا محليًا ويستعمل Playwright/Chromium.
- يملأ البيانات **بالتطبيق القديم نفسه** (`tests/fixtures/v8`) ثم يفتح الجديد ⇒ يثبت أن البيانات القديمة تُقرأ.
- ميزات الهاتف تُختبر بمحاكاة `window.Capacitor` (مثلًا `CapacitorUpdater.download/next/set` في `tests/upd.js`).
- `tests/sw-upgrade.js` ينشر «إصدارًا جديدًا وهميًا» والصفحة مفتوحة ويتأكد أنها تُظهر الرسالة وتعيد التحميل وحدها.

## 7. خطوات إصدار تحديث (بالترتيب)

1. تحقق أن الموقع ليس أحدث منك: `git show origin/gh-pages:version.json`.
2. أضف ملاحظات الإصدار إلى `CHANGES` في `extra.js` (تظهر للمستخدم كإشعار «ما الجديد»).
3. غيّر رقم الإصدار في الأماكن الأربعة (القسم 5.2).
4. `node --check core.js views.js more.js extra.js i18n.js sw.js` + فحص الترجمة.
5. `tests/run.sh` يجب أن ينجح بالكامل.
6. commit و push على فرع العمل.
7. النشر:
   ```bash
   git fetch origin gh-pages && git worktree add /tmp/ghp origin/gh-pages
   tools/publish-web.sh /tmp/ghp
   cd /tmp/ghp && git add -A && git commit -m "Deploy vX.Y.Z" && git push origin HEAD:gh-pages
   ```
8. شغّل workflow **Verify live site** واقرأ السجل: كل سطر يجب أن يكون `PASS`.
9. حدّث `PROJECT_MEMORY.md` بما تغيّر وكيف تم التحقق.

## 8. نص جاهز تعطيه لـ Claude Code لبناء تطبيق مشابه

```text
ابنِ تطبيق ويب يعمل بدون إنترنت (PWA) بـ JavaScript عادي بدون إطار ولا أدوات بناء،
بياناته في IndexedDB على الجهاز فقط، ويُنشر على GitHub Pages، ويُغلَّف كتطبيق أندرويد بـ Capacitor 6.

التحديث التلقائي مطلوب بهذه الطريقة:
1) ثابت APP_VER في ملف JS، ونفس الرقم في ?v= لكل ملف، وفي اسم كاش الـ Service Worker.
2) Service Worker: الشبكة أولًا لـ index.html مع مهلة ورجوع للكاش، والكاش أولًا للملفات ذات ?v=،
   وحذف الكاشات القديمة عند التفعيل. الصفحة تستدعي registration.update() عند الرجوع وعند عودة الإنترنت،
   وتعيد التحميل بعد التفعيل فقط إذا كان version.json أحدث، وبعد إغلاق أي نموذج مفتوح.
3) سكربت نشر ينسخ الملفات لفرع gh-pages، ويصنع app-<ver>.zip (الملفات في جذر الـ zip)،
   ويكتب version.json = {"version","zip"}.
4) في الأندرويد: @capgo/capacitor-updater في الوضع اليدوي (autoUpdate:false, statsUrl:'', appReadyTimeout:15000)،
   notifyAppReady() عند التشغيل، ثم fetch(version.json) → إذا أحدث: download → next → (بعد إغلاق النماذج) set،
   مع رسالة واضحة للمستخدم، ومحاولة مرة كل ساعة كحد أقصى وعند عودة الإنترنت.
5) workflow لبناء APK يقرأ الإصدار من الكود، ويوقّع بمفتاح دائم مشفّر في المستودع (كلمة السر في Secrets)،
   ويفشل إذا لم تطابق بصمة التوقيع البصمة المحفوظة. أضف @capacitor/app لمعالجة زر الرجوع.
6) اختبارات Playwright تحاكي window.Capacitor لاختبار التحديث، واختبار ينشر إصدارًا وهميًا والصفحة مفتوحة.
لا تكسر البيانات القديمة أبدًا: أي حقل جديد اختياري مع قيمة افتراضية.
```
